### Failed-before counterexample and expected corrected oracle [I; not executed]

The earlier ledger path allowed `UnusedAvailable` without naming buyer prepared/accepted-epoch holds: accept a 34-zatoshi max-debit order, commit root, delay MPC with **zero Fill records**, then request refund/reassign34. A whole-credit-only reservation check could release34 before final clearing even though the accepted result later requires25 seller payout; the seller-only T06b would miss this. This is a **specified design counterexample**, not an observed implementation failure. T06c's oracle rejects both operations, preserves34 held at the same generation, and rejects stale late commits/results after fenced abort/exclusion. Active immutable Final+journal activation alone partitions25 seller payout outstanding +9 buyer unused; partial payout moves only its own units final and change does not mint credit. Log exact pre/post chains, journal categories, generations and input locks when an implementation exists. No regression or scenario has run here.

**State/conservation oracle:** buyer T09 and [seller raw-atom/backing equation](../architecture/06-OFFCHAIN-SERVICES.md) must hold per disjoint unit at every event. In-flight/dispute are flags/substates, not new sums. Attribute locked input value once; canonical consumed input becomes exact provisional recipient/change effects, never original+outputs. Provisional recipient effect backs only that same outstanding payment, never another send; provisional change is not new credit/spendable before confirmation. SPL CPI-local Released is not externally observed finality: pending transfer effect exclusively backs its own outstanding portion. Track note nullifiers separately from business certificate/portion/order/authorization replay. Unknown canonical decision/unanimous acknowledgement/reorg/short backing holds/pauses/disputes, never frees value. Final-unused returnability needs matching canonical finalized result/exclusion/abort and journal activation/fence.

**Source-backed candidates, still untested:** SDK arcisEd25519 and immutable sealed-account packing/extraction do not prove runtime. Keep Rct exact ciphertext/owner/nonce/layout root, private-opening hiding Cholds membership and certified in-MPC Corder distinct. Authenticate manifest-pinned coordinator key/version on queue and **EVERY extraction**; individual results only certified one-use client key. All chunks/context/digests and whole private application plus unanimous ack are needed for AllocationActive before refunds **or** Release. No raw-map hash-as-hiding, caller-supplied whole-book owner, plaintext-derived ciphertext-root equality or oversized arbitrary callback assumption.

## 4. Cross-chain state campaigns [I]

Trace order/resource state `Available → AdmissionPrepared → EpochEncumbered → active Final split`, then **each monetary leg** `Reserved → IntentAuthorized → Sent → Final`, with exact canonical root/Final/abort/fence and private journal activation. Unknown decision or first-leg ambiguity holds/disputes; `Complete` needs both actual final effects. Distinguish SPL CPI success, transfer, finalized chain observation, ZEC signature/broadcast/mining/recipient effect and policy finality. Zoss Delivered never changes these. Model duplicated/out-of-order events, interrupted DB/chain boundaries, delayed/frozen transfer, no unanimous business decision and dead spend quorum; compare entitlements/input/change at every event, not just final status.

1. **Prepared/excluded/aborted:** uncertain commit keeps own-leg holds; no executable fill. Final immutable exclusion or canonical irrevocable **pre-Final/no-first-leg** abort fences all stale intents before applicable resource release; acknowledgements are not atomic across stores. Actual SPL transfer needs token permission; ZEC unused refund needs separate unanimous business decision/live spend quorum/inventory. Record stranded claims if any domain unavailable.
2. **ZEC-first fault comparison:** send/finalize buyer ZEC, then freeze/reject SPL or attempt an impermissible filled-SPL refund; refund rejects under honest fenced policy, but corrupt threshold/issuer may still cause buyer loss. Preserve evidence/dispute, no reversal or signed-intent-as-payment claim.
3. **SPL first:** record seller's SPL release, then quorum censorship, wrong-destination spend or reorg; identify seller exposure. A timeout cannot recall SPL or compel a shielded note refund.
4. **Near-expiry cross:** at the exact cutoff and one unit either side, interleave an *unmined* ZEC transaction expiry, a mined payout, a late signature and a Solana refund. [ZIP 203](https://zips.z.cash/zip-0203) [P] expires only unmined transactions. Never infer mined-note recovery.
5. **Restarts:** retain canonical phases/entity IDs/generations and cutoff eligibility decisions, writer lease, every signed predecessor/head/effects acknowledgement, independently retained non-rollback high-water/used business intents/signing nonces and **all potentially live signed transactions/input locks**, including distinct-note alternatives. Reconcile full allocation chunks+acks+activation and inventory/chain before any resume. Restoring pre-intent snapshots cannot make a live intent disappear; missing/inconsistent history ⇒ Disputed/halt, no same-liability second pay/nonce reuse/second writer. Unknown commit/full activation keeps both held; no timeout refund.

Candidate selects **SPL-first, one concurrent fill**, three unanimous business-decision domains, 2-of-3 native spend capability, zero participant fees/operator sponsorship, and no public price/per-order openings. Named independent operators, interoperable certificate circuit, journal/chain fault behavior, actual fees/caps/finality and informed loss terms are **unverified**, not still an unselected architectural menu. Manifest values must derive from risk/measured evidence and be approved before any transaction. Planned faults can falsify design, not prove universal safety; signatures are trusted statements, not Ironwood consensus/payment proof [I].
