## Evidence policy and execution pyramid

There is no program, binary, program test suite, deployment, or supported production mint (**U**). This is a gate specification. A test is not passed because a reference function agrees with itself; the target is the compiled on-chain program and observable token-account state. Store test fixture seed, program build hash, SVM/token-program versions, feature set, failing minimized trace, measured CU, and exact mint extension bytes with each run. Re-run the same corpus against a validator-compatible runtime when implementation exists.

1. **Pure integer examples and slow reference model:** independent host-language clearing oracle implementing §3 from the written rules, not importing the program's sort/proration functions. For small lot/price domains, enumerate every integer tick between `L_min` and `L_max` to find `V*`, `p_lo`, `p_hi`, apply exact half-even marginal-plateau midpoint, allocate marginal levels using floor and specified leftover order. Compute residual separately against the unfilled opt-in remainder and signed funded levels. Exercise hand-computed vectors and no-cross; large tick ranges use boundary/structural reasoning plus checked arithmetic tests, not unbounded enumeration. A throwaway Python reference recomputed T0–T6 as a design-time cross-check; this is not implemented CI, compiled-program test evidence or proof of correctness.
2. **Instruction and transaction cases:** [Mollusk](https://github.com/anza-xyz/mollusk) (P, retrieved 2026-09-28) for single-instruction account constraints and CU snapshots; [LiteSVM](https://github.com/LiteSVM/litesvm) (P, retrieved 2026-09-28) for complete place → close → clear → `settle_order` / `settle_maker` after `Cleared`, or place → close/guard → `RefundOnly` → `refund` (never after `Cleared`), Clock and slot manipulation, true SPL Token and Token-2022 CPIs. Negative cases must assert no mutated escrow or entitlement on failure; idempotence must assert unchanged balances and state on retry.
3. **Differential properties:** `proptest` generates bounded user/maker order books, fractional allocations and adversarial limits; compiled-program state via LiteSVM versus independent reference. Each generated case compares exact `V*`, `p_lo`, `p_hi`, `p*`, per-order CROSS and RESIDUAL lots/atoms, **one aggregate per-order fee across both phases**, unused escrow, maker-level consumption, fee split/dust and fixed entitlement ledger. Shrink to a reproducible minimal case. Reorder *instruction accounts/sorted hint* holding `(placed_slot, nonce, owner)` fixed; genuinely changing placed slots can lawfully change tie order.
4. **Stateful adversarial fuzz:** [Trident](https://github.com/Ackee-Blockchain/trident) (P, retrieved 2026-09-28) or equivalent stateful harness generates arbitrary actor sequences, instruction bytes, account substitutions, duplicated or sparse indices, malformed TLV, clock movement, issuer pause/freeze/multiplier changes, CPI failure, `SettlementBlocked`/retry, vault shortfall/`Impaired`, and rejected `refund` after `Cleared` / rejected `settle_*` before `Cleared`. At each step assert invariants on *on-chain accounts*, not only result codes. Preserve minimized failing seeds as regressions; track every lifecycle edge/error branch.
5. **Synthetic integration:** [Surfpool](https://solana.com/docs/tools/surfpool) (P, retrieved 2026-09-28) with **SYNTHETIC** local mints, including Token-2022 Scaled UI Amount plus Pausable and applicable freeze/permanent-delegate settings, a separately qualified synthetic quote mint (test both SPL Token and Token-2022 policies), and `TransferHook` mint rejection with hook program set and unset on either leg. Use deterministic local time/slot manipulation, real token instructions, UI/SDK decoding, receipts, RPC lag and indexer restart. Synthetic extension combinations must be valid under the tested token program; do not infer a live xStock mint's support. A full local validator replay is required for runtime behaviors Surfpool does not emulate exactly. No mainnet fork is evidence of permission to use a production mint.

**Formal review before release:** derive per-mint ledger/vault conservation equations and a transition model (`Open/Closed/Cleared/RefundOnly`, per-leg `SettlementBlocked` advisory marker, `Impaired`, `Unpaid/Settled`, `Finalized`) with each obligation's paid flag and each epoch's isolated vaults. Model-check finite states with independent solver or exhaustive small bounds, including non-sticky preflight blocks and shortfall stopping payouts only from affected leg; manually inspect Rust/ELF account and CPI paths. Finite models supplement rather than prove SVM behavior or economic safety.

## Test catalogue (all planned; Q01–Q21 each map one threat, Q22 tests cross-cutting entitlement integrity)

For Q01–Q22, a rejected instruction leaves balances/state unchanged; the separately defined pre-clear `RefundOnly`, per-leg `Impaired`/`VaultShortfall` and advisory `SettlementBlocked` preflight are successful transitions, not rejected instructions. There is **no `mark_settlement_blocked` instruction**. `settle_order` / `settle_maker` may be called only after `Cleared`, and `refund` only in `RefundOnly` (never after `Cleared`). Each permitted call preflights the fixed entitlement's epoch vault, mint and recipient canonical token account. Frozen vault/account, paused mint or missing/closed canonical recipient makes the call succeed without transfer, emit `SettlementBlocked(reason, leg, slot)` and leave the leg `Unpaid`; the marker is non-sticky and gates nothing. Wrong destination/mint/program reverts, never blocks. Every next permitted call re-runs preflight; the first passing call whose transfer succeeds pays the leg. Unexpected CPI failure after passing preflight reverts with entitlement retryable and is an off-chain crank/indexer incident. `clear` fixes a fully backed ledger from epoch-specific vaults only if guards show no shortfall. Pre-clear `Impaired` preserves a nominal claim equal to the original deposit with no payouts from that leg and no V1 recovery path; it may never be recoverable. Unaffected leg may continue where transferable.

## Generated clearing and accounting vectors (planned, not CI)

Generate small random user order sets with both sides, empty/one-sided and non-crossing books, duplicate limits, unequal lot sizes, marginal ties, extreme but checked tick arithmetic, and fixed `(placed_slot, nonce, owner)` keys. For a nonempty book, an independent brute-force reference enumerates **every integer tick** in `[L_min, L_max]`, computing `D(p)`, `S(p)` and `V(p) = min(D(p), S(p))`; compare the program's distinct-submitted-limit sweep and allocations with that reference. For empty books assert no cross without defining a tick interval. Keep nonempty tick ranges small enough for actual enumeration, while separately exercising checked arithmetic at large values. Compare every permutation of a small order set (or sampled permutations of larger sets) with metadata fixed; a changed `placed_slot` is a different input and may lawfully alter marginal leftover order. Shrink disagreements and preserve seeds. A throwaway Python reference recomputed the design vectors T0–T6, but this is a design-time check, not implemented CI or evidence of on-chain behavior.

- **Clearing domain and price:** maximizing ticks are exactly a contiguous interval; when `V* > 0`, `p_lo` is a submitted ask limit, `p_hi` a submitted bid limit, `p_lo ≤ p* ≤ p_hi`, and `V(p*) = V*`. For an odd-width interval (odd `p_hi − p_lo`), assert ties at its fractional midpoint round to the **even** neighboring tick (exercise both lower-even and upper-even cases). Empty bid/ask side or `V* = 0` produces no cross and absent `p_lo`, `p_hi`, `p*`.
- **Fills and price protection:** CROSS bid lots and ask lots each sum to exactly `V*`; each filled bid has `limit ≥ p*`, each filled ask has `limit ≤ p*`, and marginal-lot allocation follows price priority, floored pro-rata and deterministic leftover tie order. Identical order sets in different submission/account-hint permutations produce identical clearing and entitlements.
- **Conservation and fee ledger:** for each funded order/maker obligation and mint leg, **original deposit = transfers funded from that deposit to the opposite side + refund to depositor + fee retained**, in raw atoms; base deposits and maker obligations have zero fee. The payout funded by a deposit is not necessarily a payout **to its depositor**: a seller's base deposit funds buyers, while sellers receive quote from bid deposits. Reconcile all funded deposits, outgoing payouts, owner refunds and fee movements per leg; assert no base atoms are created or lost. Reconcile fee-vault total to the sum of one aggregate fee per user order on CROSS + RESIDUAL notional, and to the protocol + distributor (or protocol fallback) + crank split shares **plus dust**. A RESIDUAL maker is uncharged, unlike both charged sides of a CROSS lot. Separately assert recorded liabilities plus fees reconcile to each leg's recorded funded vault balance at clear, excluding quarantined unsolicited surplus.
