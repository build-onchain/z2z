## Execution model and derivations

One program checks exact account owners/mints/token programs on **both** legs, timestamps, paid bits and authority privileges. The program computes price, user allocations, residual fills and vault-backed fixed entitlements. A crank supplies at most verified order-index permutations, never a clearing price. Choose Anchor for fast IDL/schema iteration or Pinocchio for footprint only after benchmarking; either must implement identical checked arithmetic and account layout. [INFERENCE] Do not assume an Anchor zero-copy attribute automatically handles Token-2022 variable-length TLV; parse mint extensions separately under owner/type/length bounds.

| Address | PDA seeds under Kerb program, or standard ATA derivation | Authority and invariant |
|---|---|---|
| `Config` | `['config']` | Timelocked governance pubkey, guardian pause-new-orders bit, caps/fee constants. No withdraw instruction. |
| `Market` | `['market', base_mint, quote_mint]` | Exact mints and **separate** base/quote token program IDs; one qualified program-owner pair per mint. Refuse any mint with a permanent delegate set or a `TransferHook` extension in V1. Extension/authority snapshot; raw lots, quote tick, guards. |
| `Epoch` | `['epoch', market, epoch_index_le_u64]` | Provisional scale target: 64 orders and 4 makers in bounded state, pending LiteSVM/SBF CU and transaction-size benchmarks; immutable result after clear. Hackathon MVP: ≤8 user orders, 1 maker, 1 level per side. |
| `EpochAuthority` | `['epoch_authority', epoch]` | PDA signer solely for exact epoch vault transfers, never a governance signer. |
| `BaseVault` / `QuoteVault` | ATA `(EpochAuthority, base_token_program, base_mint)` / `(EpochAuthority, quote_token_program, quote_mint)` | Token-account owner = EpochAuthority, mint/program bound on every call; separate per epoch. Vaults must be qualified against default frozen state and confidential/fee behavior; a `TransferHook` mint is refused before vault creation. |
| `FeeVault` | ATA `(EpochAuthority, quote_token_program, quote_mint)` would collide with `QuoteVault`, so use **separate** `FeeAuthority=['fee_authority',epoch]`, ATA `(FeeAuthority, quote_token_program, quote_mint)` | Only fixed fee claims; fee dust is tracked explicitly. No generalized sweep authority. |
| `UpgradeAuthority` | Externally configured multisig/timelock, not derived from market | Program upgrade authority, a governance/code risk despite instruction-level admin restrictions. |

Do not fund market or epoch from user collateral implicitly. Rent payers may be distributor, crank or user but have no authority over deposits; rent refunds after finalized account closure go to recorded rent payer only after all payout obligations are zero. [INFERENCE] Account closing itself must not become a route to vault withdrawal.

This is a **SYNTHETIC-test-mint design only** at present. Production eligibility is **BLOCKED** because no exact mainnet xStock or other issuer mint has passed the allowlist; neither this PDA layout nor the general xStocks documentation qualifies any named mint ([`05-TOKEN-2022-ISSUER-INTEGRATION.md`](05-TOKEN-2022-ISSUER-INTEGRATION.md)).

## Byte layout, zero-copy and ledger

**Proposed `repr(C)` fixed-width, eight-byte-aligned layout** (including eight-byte discriminator at offset 0). These are **design sizes**, not actual compiled `size_of` measurements; static assertions and IDL/codec roundtrips must prove offsets and sizes before use. Store `u128` computations in registers, then range-check ledger fields into `u64`. Little-endian integers, zeroed padding, explicit discriminants and version, no Rust `bool`, `Vec`, heap-owned strings or unstable enum layout in account data. Proposed **scale-target** Epoch slab is **15,456 bytes** before vault token accounts and rent: header 256 + 64×208=13,312 + 4×472=1,888. [INFERENCE] Allocation of this slab in one instruction may exceed runtime/Anchor CPI growth constraints despite fitting the maximum account size; measure with LiteSVM/SBF CU and transaction-size benchmarks. If needed, split it into order pages and a smaller Epoch header/maker account without changing economic semantics; proposed scale bounds themselves require benchmark validation.

| Layout | Fields and offsets (bytes) | Size |
|---|---|---:|
| `Config` | discriminator `0..7`; governance multisig `8..39`; pause guardian `40..71`; timelock minimum seconds, fee bps, order cap `72..95` (3×u64); maker/level caps and status/version `96..103`; reserved `104..127` | 128 |
| `EpochHeader` | discriminator `0..7`; market pubkey `8..39`; epoch index `40..47`; open/close/deadline `48..71` (3×u64); base fingerprint `72..103`; `p_lo,p_hi,p_star,V_star` `104..135`; recorded funded base/quote `136..151`; fixed fee quote and summed base/quote payout obligations `152..175`; order count `176..177`, maker count `178`, state `179`, per-leg impairment/blocked flags `180..183`; reserved `184..255` | 256 |
| `OrderRow` | owner and distributor `0..63` (null distributor sentinel); nonce, placed slot, quantity, limit, deposited base, deposited quote, primary lots, residual lots, primary quote notional, residual quote notional, base payout, quote payout, fee quote: **13×u64** at `64..167`; side, opt-in, state, paid bits `168..171`; latest advisory base/quote block reason `172..173`, reserved `174..175`; attribution-policy-dependent reserved pubkey `176..207` (meaning undecided, canonical §3.9) | 208 |
| `MakerLevel` | price, original lots, remaining lots: 3×u64 | 24 |
| `MakerRow` | maker pubkey `0..31`; posting slot and maker nonce `32..47`; escrow base, escrow quote, base payout, quote payout `48..79`; 8 bid levels + 8 ask levels `80..463`; state, paid/refund bit fields, latest advisory base/quote block reasons and zero padding `464..471` | 472 |
| `Market` | discriminator `0..7`; base mint `8..39`, base token program `40..71`, quote mint `72..103`, quote token program `104..135`, extension/authority fingerprint `136..167`; `base_lot_raw`, `tick_quote`, `epoch_len_s`, `guard_s`, `clear_grace_s`, `next_epoch_index`, qualification slot: **7×u64** at `168..223`; Config pubkey `224..255`; base/quote decimals, flags and bumps `256..263`; reserved `264..319` | 320 |

For each order, `base_payout`/`quote_payout` include matched base/quote plus unused deposit; a canceled order stores a paid cancellation bit and is excluded from clear. For each maker, payouts include sales proceeds and remaining ladder deposits. The order's `fee_quote` is the **single ceil fee on aggregate CROSS+RESIDUAL notional**. Which caller receives the settlement-crank share and how that claim is recorded remain open (canonical §3.9); the reserved row field does not decide it. A CROSS lot charges two user sides (~10 bps of CROSS notional); a RESIDUAL lot charges one user side and a zero-fee maker (~5 bps of RESIDUAL notional). The residual fee plus distributor rebate could make routing worse than trading the same maker directly; alternative fee policy is undecided in product ADR-009. At solvent clear the **recorded funded** ledger satisfies `Σ order.base_payout + Σ maker.base_payout = recorded_base_escrow` and `Σ order.quote_payout + Σ maker.quote_payout + Σ user_fee_quote = recorded_quote_escrow`. Move `Σ user_fee_quote` from the per-epoch quote vault to the per-epoch fee vault atomically; remaining nominal quote payouts are backed by recorded deposits, while fee shares plus dust equal moved fee. Check `actual_vault_balance ≥ outstanding_entitlements` at each guard and settle; equality is not required because unsolicited direct deposits are quarantined as excess, neither fee nor claim. If `actual < outstanding`, that **leg** becomes `Impaired`, its payouts stop, `VaultShortfall(actual, outstanding, uncovered)` is emitted, its nominal entitlements remain unchanged and the other leg continues independently. Before clear, each escrow owner instead retains a nominal claim equal to the original deposit on the impaired leg; it may never be recoverable. A shortfall before clear supersedes RefundOnly for that leg; after clear it cannot unwind the result. V1 has no impaired-leg recovery path.

The header records funded base/quote and fixed fee, not a promise that issuer authorities will preserve vault balances. `u64` payout fields are capped by recorded signed deposits, **not** unsolicited vault donations. A token program can allow direct deposits into a PDA-owned token account; track any excess over recorded liabilities as quarantined surplus, neither fee nor claim. Who may sweep it, when and where remain undecided (canonical §3.9); no general admin sweep is defined. An `Impaired` leg cannot be finalized as paid; impaired recovery likewise remains an open policy.

## Instruction surface and precise authorization

Notation: `S` signer, `W` writable, `R` read-only; all account owners, PDAs, bumps, mint addresses, token programs and ATA authorities are verified, not trusted from client labels. The fee payer may differ from the instruction's economic signer. No hook extra accounts or user-chosen arbitrary CPI programs in V1. An optional v0 ALT reduces address bytes, never signer/owner verification.

| Instruction | Signers and writable accounts | Critical checks and effect |
|---|---|---|
| `create_market` | Timelocked governance S; payer S/W; Config R; Market W; mint accounts R | Qualify exact mints/token program owners/extensions; **reject any base or quote mint with a `TransferHook` extension (set or unset hook program) or permanent delegate set**; snapshot authority fingerprint, scales, guard; reject duplicate/ineligible profile; no creation based on ticker. |
| `open_epoch` | payer S/W; Market W; new Epoch W; **epoch-specific** vaults W as created; mint R | Re-check both mint extension/authority fingerprints against market qualification; mismatch blocks opening pending requalification. Market not paused/blocked, no overlapping active epoch, activation guard outside epoch envelope, bound close/deadline; initialize vaults unique to market and epoch. No issuer-halt oracle. |
| `place_order` | owner S; owner source W; Epoch W; side vault W; base/quote mint R; matching token program R | Open and before close; unique `(owner,nonce)` even if prior order canceled; provisional scale target 64 live orders, hackathon MVP ≤8; `u128` escrow proof, fee reserve; `transfer_checked` exact raw deposit before slot registration. |
| `cancel_order` | original owner S; Epoch W; side vault and owner destination W; mint/program R | Open only, unspent order, exact token destination owner; return original deposit and mark canceled atomically; failed transfer rolls back. |
| `post_ladder` | maker S; sources W; Epoch W; both vaults W; mints/programs R | Open; provisional scale target ≤4 makers, ≤8 positive levels/side with unique prices per maker/side; hackathon MVP 1 maker, 1 level/side; signed epoch/maker nonce; sum bid quote + ask raw deposits; no partial active posting. |
| `cancel_ladder` | original maker S; Epoch W; both vaults and maker destinations W; mints/programs R | Open only, return original deposits atomically and mark inactive; any replacement is cancel then new funded post while Open. |
| `close` | any payer S; Epoch W; Market W (only if blocked), mint R; epoch vaults R | At/after close; fingerprint and multiplier/transfer-state preflight plus vault ≥ outstanding-escrow check. Valid → Closed; ordinary guard failure → RefundOnly; shortfall → affected leg `Impaired`, emit `VaultShortfall`. |
| `clear` | any payer S; Epoch W; epoch vaults W; fee vault W; mints/programs R | Closed and before deadline; re-check guards and solvency; verify hint permutation; recompute CROSS then RESIDUAL, ledger conservation against **recorded escrow**; move fixed quote fees to fee vault atomically; store Cleared. Invalid hint fails without state writes; ordinary issuer guard → RefundOnly, shortfall → affected leg Impaired without clearing. |
| `trigger_refund_only` | any payer S; Epoch W; vaults R; mints/Market R/W as needed | Open/Closed only; deadline expired or provable pre-clear guard failure; no discretionary admin override. Vault shortfall instead marks affected leg Impaired. |
| `refund_order` / `refund_maker` | any payer S; Epoch W; corresponding epoch vault/canonical recipient W; mint/program R | Only in RefundOnly, never after Cleared; solvent leg, one original-deposit recipient leg per instruction, split across transactions. Verify canonical destination for recorded owner, mint and program; wrong destination/mint/program hard-reverts. Re-check solvency and deterministic preflight; shortfall marks leg Impaired, deterministic obstacle emits advisory `SettlementBlocked` without payout, successful transfer marks Settled. |
| `settle_order` / `settle_maker` | any payer S; Epoch W; corresponding epoch vault/canonical recipient W; mint/program R | Only after Cleared, never in RefundOnly; one recipient leg per instruction across transactions. Re-check per-leg solvency, then deterministic preflight over entitlement-fixed vault/mint/canonical account. Wrong destination/mint/program hard-reverts, not a block. Shortfall records Impaired and stops that leg; preflight obstacle emits advisory `SettlementBlocked` and leaves Unpaid; passing preflight and successful exact transfer marks Settled. |
| `claim_fee_share` | any caller S; Epoch W; per-epoch fee vault and qualified recipient W; quote mint/program R | Per-order, per-role paid bits; compute fixed floor shares, redirect null distributor to protocol; settlement-crank recipient/claim attribution is open (canonical §3.9), not first-settlement-by-default. Check fee-vault solvency, preserve dust; shortfall impairs fee leg rather than racing claimants. |
| `finalize_epoch` | any payer S; Epoch W | All order/maker payouts/refunds and fee shares resolved; emit terminal state, dust accounting, release rent only under checked policy. |
| `pause_new_orders` / `unpause_new_orders` | timelocked governance S or bounded guardian for emergency pause; Market W | Affect new orders/epochs only; **not** clear/settlement/refunds or stored entitlements. |

The settlement-crank share cannot be attributed by an assumed first caller; recipient and claim recording need a decision under canonical §3.9 before implementation. A zero-value payout sets its own completion bit without CPI. `settle_*` and `refund` pay at most one recipient leg per instruction, across multiple transactions; do not mark both paid after one succeeds. Derive the canonical recipient token account from the entitlement's economic owner, leg mint and recorded token program; verify the supplied account equals that address and matches owner/mint/program. Wrong destination, mint or program hard-reverts and never records a block. Deterministic preflight checks vault frozen, recipient frozen, mint paused and recipient missing/closed. On a preflight obstacle the instruction succeeds without transfer, emits `SettlementBlocked(reason, leg, slot)`, stores only the latest advisory non-sticky reason and keeps the entitlement `Unpaid`. The marker gates nothing: every later attempt repeats preflight, and the first attempt with passing preflight and successful transfer marks `Settled`. Anyone may recreate a missing canonical recipient account. An unexpected CPI error after passing preflight reverts, leaves the entitlement retryable and must be surfaced by crank/indexer as an off-chain incident.

## State transition and deadlines

```text
Open -- close_ts/valid close --> Closed -- valid clear before deadline --> Cleared
  |                               |                                      |
  | ordinary guard/deadline       | ordinary guard/deadline              | per-leg settlement
  +-------------------------------+--> RefundOnly                        | preflight obstacle: advisory
                                      | one original-deposit leg/ix        | SettlementBlocked; remains Unpaid
                                      +--> Finalized when all refunded    | retry -> Settled on successful transfer
                                                                         +--> Finalized when all claims paid
  Per-epoch base, quote or fee vault shortfall at any guard/settle:
  affected leg -> Impaired + VaultShortfall; payout stops; nominal claim unchanged;
  pre-clear claim = original deposit, possibly unrecoverable; solvent leg continues.
  No post-clear reversal or RefundOnly.
```

`SettlementBlocked` is an advisory, non-sticky marker on an unpaid leg, not a transition away from the stored `Cleared` result or a retry gate. `Impaired` stops payout on its leg; before clear it supersedes RefundOnly for that leg and preserves each owner's original-deposit nominal claim without a V1 recovery path. A pre-clear timeout never fabricates an auction. A post-clear timeout never activates RefundOnly. Re-check extension/authority fingerprints at `open_epoch`, `close` and `clear`: mismatch at opening blocks new epochs pending requalification; mismatch before clearing an existing solvent epoch sends it to RefundOnly; mismatch after clear blocks new epochs until requalification but does not block `settle_*` of fixed entitlements, which still runs freeze/pause/recipient preflight. At no point may governance change stored `p*`, `V*`, fills or entitlement amounts.

## Sort hints and resource budget

A crank may supply sorted permutations for bids, asks and maker levels. Validate each length, index range, uniqueness/coverage against **all active records**, exact side, and adjacent ordering by `(price priority, placed_slot, nonce, owner)` or `(maker price, posted_slot, maker)` respectively. Primary clearing sorts and sweeps **distinct submitted limit prices**, not all integer ticks: O(n log n) with in-program sorting, O(n) after verified hint. The maximizing integer-tick interval `[p_lo,p_hi]` has submitted ask/bid endpoints; `p*` is its half-even marginal-plateau midpoint and remains inside it. If either side is empty or `V*=0`, no cross and all three prices are absent. Allocate maker price groups from funded remaining amounts. Incorrect hint errors without modifying results; never use an off-chain supplied `V*`, marginal quantity, price or fee. Duplicate maker level prices per maker/side and duplicate `(owner,nonce)` are refused so time keys are total.

For residual maker levels at the same price, use the marginal-lot rule of canonical §3.3 step 6: proportional to remaining level quantity, floored to whole lots, with leftover lots by `(posted_slot, maker)`. This applies only after primary allocation and cannot change `V*` or `p*`.

**[INFERENCE] Provisional scale targets, not measured CU or guaranteed fit:** 64 orders/epoch and 8 levels per side × 4 makers. Hackathon MVP bounds: ≤8 orders, 1 maker, 1 level per side. A scale-target 64-order/64-level clear has ≈15.5 KiB proposed account state, plus mint TLV and three vault token accounts. Profile LiteSVM/SBF compute units and transaction size at MVP and 0/1/32/64 order and 0/4/64 maker-level cases including worst-case price ties and permissioned TLV parsing. Tentative development budgets: placement/cancel ≤150k CU, close ≤100k CU, clear ≤1.2m CU, one-leg settle ≤200k CU; **release gates are observed maximums with headroom**, not these figures. The scale target must fit measured program CU/account locks/wire format before adoption; if not, revise implementation or proposed bounds explicitly rather than silently asserting fit. Settle/refund pays one recipient leg per instruction and splits an epoch across transactions. Transfers with hooks and ATA creation must be separately qualified and metered.

Legacy/v0 have a 1,232-byte transaction envelope. v0 address lookup tables help carry large account lists **but not** oversized instruction data and do not expand CU. v1 allows 4,096 bytes and 64 inline accounts but **does not support ALTs**; it requires explicit compute-unit and loaded-account-data limits and wallet/provider support. On 2026-09-28 Solana's September 2026 guide reports activation, but check per-cluster feature gate and tooling before use ([Solana larger transaction sizes](https://solana.com/upgrades/larger-transaction-sizes), retrieved 2026-09-28). `clear` should pass compact index hints (e.g. ≤64 u8 indices per side), not serialized orders; if account-list or CU constraints break the provisional 64-order scale target, measure and revise the proposed bound or implementation rather than delegating computation off-chain. Indexers consuming v1 must use integer `maxSupportedTransactionVersion: 1`, parse `transactionConfig` and avoid silently treating it as v0 (same source).

## Errors and event contract

| Error family | Examples and handling |
|---|---|
| Authorization / identity | `WrongMarketMint`, `WrongTokenProgram`, `WrongVaultAuthority`, `WrongOwner`, `DuplicateNonce`, `InvalidDestination`, `InvalidSigner`; fail atomically. |
| Lifecycle / caps | `NotOpen`, `EarlyClose`, `ClearDeadlineElapsed`, `AlreadyCleared`, `NotRefundOnly`, `OrdersFull`, `MakersFull`, `LevelsFull`; verified state, never admin repair. |
| Economic / hint | `ZeroQuantityOrPrice`, `ArithmeticOverflow`, `EscrowInsufficient`, `InvalidPermutation`, `InvalidLevelOrder`, `LedgerConservationFailed`; no truncated transfer. Solvency shortfall is persisted `Impaired` with event, not a failing instruction that rolls back its own alarm. |
| Issuer guards | `UnqualifiedExtension`, `PermanentDelegateSet`, `FingerprintMismatch`, `MultiplierGuard`, `MintPaused`, `AccountFrozen`; before clear ordinary guard → RefundOnly; after clear fingerprint mismatch blocks new epochs until requalification without blocking settlement, while freeze/pause preflight may record a blocked leg. |
| Token CPI after preflight | Propagate CPI failure; entire instruction rolls back and the unpaid entitlement remains retryable. Crank/indexer surface unknown cause as an off-chain incident, never a fabricated on-chain block. |

Emit versioned `MarketQualified(mint,program,profile_hash)`, `EpochOpened`, `OrderPlaced/Cancelled`, `LadderPosted/Cancelled`, `EpochClosed`, `EpochCleared(V*,p_lo,p_hi,p*,cross_lots,residual_lots,ledger_digest,fee_total)`, `RefundOnly(reason)`, `VaultShortfall(epoch,leg,actual,outstanding,uncovered)`, `LegImpaired(leg)`, `SettlementBlocked(reason,leg,slot)`, `LegSettled(order_or_maker,leg,base_raw,quote_raw,phase_breakdown)`, `FeeSharePaid(role,amount)`, `FeeDust(amount)` and `Finalized`. `SettlementBlocked` is emitted by a successful no-transfer preflight obstacle and is advisory, not proof of a lasting block; a wrong destination/mint/program is a hard error. An event is not proof of finality until its transaction is rooted; the ledger account determines payment state. Include phase labels in receipts, not promises of external savings.

## Upgrade and custody constraint

The upgrade authority is an announced multisig **with timelock**; market-add and pause-new-orders authorization is distinct from epoch-vault signing. No `admin_sweep`, editable clearing result, pause-refund or unilateral crank whitelist. Upgradeability remains a substantial trust assumption: independent source review, disclosed delay, transaction simulation and user exit opportunities precede any live market. Settlement core can be frozen after audit only if code and legal decisions justify doing so; no audit or deployment exists yet.

## Open issues against 00-CANONICAL

- **Unsolicited token transfers:** Surplus above recorded liabilities is quarantined, neither fee nor claim; the ledger proves `vault_balance ≥ outstanding_entitlements`, not equality. Who may sweep it, when and where remain open (canonical §3.9). No general admin sweep or user absorption of excess is specified.
- **Settlement-crank fee attribution:** The 1/10 fee recipient (clear caller, each settlement caller or a split) and claim recording remain open (canonical §3.9). No first-settlement rule is assumed.
- **Impaired recovery and off-chain halts:** V1 has no impaired-leg recovery path. Halt source selection, open-epoch handling and notification remain undecided; no halt oracle exists (canonical §3.9).
