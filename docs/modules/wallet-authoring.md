# Wallet authoring — crates/zcash và P/Q phía U

**Owner contract; actual native primitives, financial acceptance chưa đạt.** `crates/zcash` có Ironwood/v6 P/Q authoring, complete local Q proving/signing/extraction và independent sender-output recovery. `crates/proofs` có deterministic private preparation relation; `crates/runtime::custody` có encrypted immutable preparation save/restore. Những primitives này **không** là chain-valid note, S-independent wrapped certificate, funded authorization gate hoặc full manual wallet. Proposed samechain note authoring bên dưới là relation mới, không implementation đã có.

**Active lane scope:** L-ZEC native ZEC is an active first-class lane in the whole pipeline (not V2), with pairs ZEC↔{Base, HyperEVM, Solana, NEAR}; `crates/zcash`/`crates/runtime::custody` are the authoring/custody modules for it. L-HEVM, L-SOL, L-NEAR and X.CROSSCHAIN (HTLC first, all pairs in parallel, no atomicity/privacy claim) are active parallel lanes; wrapped/bridged ZEC never substitutes.

[ARCHITECTURE](../ARCHITECTURE.md) owns behavior, [MODULES](../MODULES.md) packaging, [BLOCKERS](../BLOCKERS.md) enablement, [native status](../NATIVE-IMPLEMENTATION-STATUS.md) observed evidence. [SERVER-INDEPENDENCE](../SERVER-INDEPENDENCE.md) owns bundle/lifetime/manual-stage requirements; [research](../research/SERVER-INDEPENDENCE-RESEARCH.md) explains data/prover limits. Tài liệu này không authorize ký, gửi, deployment, funding hoặc cấp private witnesses cho người mới.

## 1. Role và interface tối thiểu

**Wallet/native client owns authorization and recovery.** Source functions dựng P/Q và kiểm local relations; wallet-local caller binds quote/context, reserves note, stores private witnesses, independently checks destination rồi mới releases exact P authorization. Proof implementation thuộc [proof module](zcash-proofs.md); target reading/building thuộc [destination module](destination-settlement.md). Solver không giữ U wallet keys hoặc quyết định wallet consent.

### Route-1a local C/R capabilities — active one-route release

The active [release contract](../V1-RELEASE-CONTRACT.md) selects fresh2-of-2 J under the accepted bounded-window terms; the P/Q sections below remain earlier mechanism/provenance, not an override. `zcash::joint_spend` builds and independently reviews fully specified deferred Ironwood/V3 effects, derives the maintained real v6 sighash/action alpha, accepts a matching external aggregate, and later attaches owner-local membership before genuine proof/full transaction extraction. Received pre-parent review requires absent J anchor/witness; genuine padding remains verified. This is not authentic chain membership/finality or financial release authority.

`zcash::funding::prepare_joint_funding` now prepares one exact unsigned F from a caller-owned V3 wallet note and all explicit J/change/output plans, reusing the existing builder and sender witness. `PreparedJointFunding` exposes the **actual generated J note/opening, memo and shuffled requested-output mapping before any positive-owner signature or proof**. Build R from that exact J, not a separately fabricated rho/rseed: rebuilding F can change J and invalidate its early R. Complete private F contains the existing wallet's FVK/input/path and must not be sent as fresh-J auxiliary material. `complete_borrowed_owner` borrows only the actual funding-wallet ask, signs genuine padding/all required actions, proves/extracts unchanged F and verifies original anchor/effects/J/ciphertext/memo; it never reconstructs a full J ask or submits anything. Durable early R and independently verified source/financial/lifetime preflight remain mandatory caller gates, not attested by this source-only API.


`FinishedJointSpendExpectation` and `review_finished_joint_spend` review a raw finished C/R handoff without receiving its private PCZT: require independently retained J/source/payout/fee/memo terms, the sighash derived by the prior local semantic review, a separately selected anchor (v6 effects exclude it), and complete ordered V3 output openings including zero padding. `ReviewedJointSpend::output_notes` captures those sensitive openings before completion; actual bilateral exchange still needs its explicit per-swap fresh-J grant. The reviewer verifies canonical full bytes, exact effects/anchor/fees, unique J nullifier, note-ciphertext/commitment/ephemeral-key/memo recovery and every action/binding/Halo2 authorization. Outgoing ciphertext is opaque with OVK=None: all its bytes are bound by retained effects/sighash, not semantically decrypted by note+esk recovery. No wallet key or receiver IVK is required by this handoff verifier.

Success is static local semantic/cryptographic review, **not** J funding/unspentness, current anchor admissibility, source inclusion/finality/winning C/R, ETH arming/payout/return, durable recovery or gate advancement. Actual evidence and remaining qualification are recorded in [native status](../NATIVE-IMPLEMENTATION-STATUS.md).

`runtime::native_recovery` now preserves fully signed early R and finished R as **separate immutable encrypted files**, using the existing strict Linux publisher and distinct `ziquid.nativeR.v1\0` envelope. `RecoverySelection` is independently held local session/quote/chain/deployment/stage/prior-sighash data; `joint_spend_terms_digest` canonically commits actual source/J/FVK/group/payout/memo/fee-rule terms. Save succeeds only after authenticated semantic readback/durability; load requires independent selection/terms, exact encrypted-file digest and, for finished R, separately selected anchor and supplied verifier. Full early signatures and matching finished effects/proof are rechecked; output openings are recovered from reviewed early bytes, not a second opaque note codec. Raw shares/nonces/DKG packets are not persisted.

`save_preauthorized/load_preauthorized` restore the existing reviewed source capability for later local membership completion; `save_finished/load_finished` restore the existing cryptographically/semantically checked consensus transaction. Restart checks exercised both with independent pins and unchanged ciphertext. These labels are not authenticated quote negotiation or financial state: no native journal fence, consumed-right reconciliation, original-history/target proof kit, offline-media qualification or full R5/company-off funded recovery follows. Actual per-swap material grants and independent current source/target verification remain required.

**Before funding or releasing an executable capability**, store an encrypted owner-local recovery bundle and actually read/restore it. Public manifest có exact code/program/VK/PK/source/toolchain/network/history/ABI identities và retained public artifact bytes; private phần giữ đủ secrets/witnesses/authorization records. Hash/CID/path alone không data đã lưu. S cũng cần its own independent recovery/terminal capabilities trước arm; U backup không thay S prerequisites.

Existing custody protects preparation only: borrowed encryption capability, opaque filename, independent namespace/context, immutable publication and authenticated restore. Linux private-directory/descriptor-relative durability rules remain; final filenames không dùng reserved dot-prefixed staging namespace. Same-UID/root compromise, real filesystem durability, private backup retention and loss of decryption key outside guarantee; không claim mọi parsed allocation bị erased. Wallet and solver stores/key scopes disjoint. Never private PCZT/FVK/seed/openings/raw source mapping in argv, public log/queue/status/transport.

Persist transition intent **before** sign/export/send can escape, then retain exact bytes and reconciliation state. Durability failure/Unknown is not permission to release P or recreate economic intent. Quote/source expiry, job acknowledgment hoặc new SDK version không delete witness/release record; retain usable original resources until actual terminal/finality, with reviewed private-retention policy.

## 3. Invariants và transitions

### Native P/Q ordering

1. **Draft → RecoveryPrepared:** qualify one genuine valid available U Ironwood note; prepare exact unsigned P/complete local Q; durably retain independent U witness. S must independently validate same-real-input/all-self-output/fee/ciphertext/context evidence and usable Q **without U FVK**. Q export needs explicit early-cancel/fee consent. Current local primitive success alone không closes financial gate.
2. **RecoveryPrepared → DestinationArmed:** S irrevocably prefunds exact obligation and stable one-real-note reservation. U independently checks actual immutable deployment/program/verifier/beneficiaries/amount/finality and source packet lifetime. Cancellable/short/wrong funding hoặc stale API assertion không permits P authorization.
3. **Armed → SourceResolutionPending:** persist exact release/signing intent, authorize/complete/release P only after gate, retain immutable signed bytes and Unknown outcomes. Ordinary rebroadcast keeps exact effects; no silent fee/input/output/expiry/branch replacement. A separately permitted same-effect proof/auth update needs actual witness/capability and validation, not just retry label.
4. **Resolve actual P/Q/T:** same v6 effects/new auth/anchor vẫn P; arbitrary different-effect T may pay S. Earlier admissible bound P/T remains evidence once obligation funded; no artificial activation lower cutoff. U using another wallet/self-paying before funding does not force S to fund and is not prevented by this client's ordering.
5. **Terminal only from verified asset effects:** [proofs](zcash-proofs.md) authenticates full history/classification/net consideration; [destination](destination-settlement.md#3-allocation-và-actual-transfer-invariants) verifies/consumes/transfers fixed shares atomically. Q broadcast/mempool/proof flag/credit/receipt is not paid/refunded. Q self-return is specific to validated Q; arbitrary T need not return U source principal.

One genuine note backs one obligation **within the selected deployment across supported versions**. Stable secret-derived tag/relation and atomic target reservation must enforce this; local note lock or new `orderId`/salt is insufficient. Other deployments/targets chưa supported, không global uniqueness claim.

| Failure/observation | Wallet behavior |
|---|---|
| P executable before arm; wrong note/pool/dummy; incomplete Q auth/self-output/ciphertext/fee | Reject preparation/export or funding prompt; no master-key workaround. |
| Source anchor/branch/expiry/fee unusable before fund/release | Do not fund/release on claimed readiness; locally prepare/reverify allowed packet. Anchor age alone is not invalidity. |
| After arm, Q unusable/U offline, classification Unknown or history unavailable | Retain original rights/data; nonterminal pending, not timer/admin refund. Missing permanent terminal capability was an admission blocker, not a supported “finished recovery”. |
| Source reorg/competing view or funding/submission Unknown | Acquire authenticated complete history/state and reconcile exact operations; no replacement from missing response. |
| Destination transfer fails/reverts/OOG | Keep valid entitlement, beneficiaries and witnesses retryable; no opposite allocation or deletion. |

### Proposed samechain owner authoring — distinct relation

For actual assets controlled by a qualified programmable-chain ledger, wallet would prepare owner notes, exact deposit/withdraw/fill/cancel consent and recovery data. This **does not reuse native P/Q as a bridge or make legacy ZEC custody trustless**.

- **Current V1 signed-bilateral Fill2 construction:** once exact fill execution is independently approved, each recipient prepares/checks/backs up its exact outputs. Reuse [reviewed construction](../superpowers/specs/2026-10-06-independent-owner-fill-design.md) and [actual protocol](../../crates/protocol/src/samechain/fill.rs)/[owner codec/relation](../../crates/proofs/src/samechain.rs): agree public packet body B and canonical FillExecution E frame2, independently generate nonzero owner-local salt, compute own leaf from authenticated input policy, exchange only ordered opaque A/B leaves and permitted public descriptors, then compute C/freeze identical packet. OwnerWitness frame2 contains packet/E/leaves/own_salt and own capability, never counterparty policy/salt or complete Terms/common blind. `review-fill --packet FILE --execution FILE --role a|b --witness-stdin` requires separately selected canonical E and exact embedded packet equality before fresh consent bytes. Native owner relation/atomic authority source exist, but durable backups, genuine proofs/admission and full funded lifecycle are unqualified. E includes counterparty-visible quantities; no GD2 secrecy/backing claim.
- **Implemented private snapshot (2026-10-06, generated keys).** `ziquid_runtime::samechain::backup::{SnapshotOperation, SnapshotScope, HistoryPin, SnapshotSelection, save_snapshot, load_snapshot, BackupError}` stores and restores one complete existing witness per immutable encrypted file, using domain `ziquid.samechain.backup.v1`.
  - The caller supplies the selection independently. It is never inferred from ciphertext.
  - The unsigned reviewer runs before save and after load. Zero consent is preserved. Nonzero consent must pass the strict signed predicate and is never repaired.
  - `samechain::OwnedOwnerInput` is the one public owning enum, with redacted Debug.
  - The shared custody publisher is crate-private.
  - Exercised scope is recorded in [native status](../NATIVE-IMPLEMENTATION-STATUS.md). None of this is release, journal, offline-kit or funded recovery behavior.
- Complete authenticated recovery data must be independently available; local recipient decrypt/opening/commitment check **before authorization** establishes recoverability for the selected exact output. Hash binding or value conservation alone is insufficient. Do not assume a generic ciphertext-correctness ZK circuit: circuit-enforced encryption is an **unselected alternative** for future unattended partial fills. Wrong-key/zero/mismatched ciphertext must block owner consent.
- Rebuild commitments/nullifiers/authenticated roots from independently authentic chain history; current syncing/openings/eligible witnesses remain necessary for **new** proofs without a company-only indexer. Selected proposed [samechain root policy](../SERVER-INDEPENDENCE.md#32-data-availability-là-protocol-requirement) retains every authenticated historical membership root/tree generation immutably in the same deployment, no sliding expiry/admin pruning. Input/output tree domains must be bound and nullifiers globally deployment-scoped against per-tree replay. Target still checks live capability generation/cancel/capacity, rejecting unaccepted/orphan roots, spent/canceled backing and explicit signed expiry. Unbounded accepted-root state growth requires measured storage/gas/sync/rollover qualification; native Zcash anchors/Q/source lifetime do not inherit this policy.
- Fill/cancel/withdraw atomically consume/invalidate the same shared backing/intent generation. Included cancel invalidates all outstanding F1/F2 digests on that generation, even with different fees/relayers/proof representations, and creates authorized owner successor/actual withdrawal. Packet-only revocation does not cancel the order or release backing; [§4.3](../SERVER-INDEPENDENCE.md#43-cancel-partial-fill-và-race) owns this rule. Partial fill is retained: each known fill produces fresh exact successor value/openings/remaining liability and allowed quantity, checked and authorized by the respective owner; old capability/fresh random note cannot reset fill capacity. Canonical inclusion decides race; cancel cannot undo delivered fill.
- This adds an owner roundtrip for every **new** exact fill; an offline owner does not prevent submission of an already fully authorized exact packet under a retained accepted root after unrelated appends/tree rollover, without private proof renewal/secret export/new signature, subject to live backing/expiry checks. Relay automation starts only after complete authorizations and cannot rewrite outputs/fees; no offline matching-liveness or inclusion claim.
- **Fill-only artifact cutover:** [guest mode0](../../crates/proofs/methods/samechain/src/main.rs) is byte0 + one OwnerWitness frame2; execute/prove separately compare `--packet` to its embedded frozen packet. Fill journal/consent relation fields are2 within outer frame1; note/order/policy/tree/AEAD/ciphertext and creation/single-owner/withdrawal witnesses/blinds remain1. Preserve [original fill1 bytes/ELFs/binaries](../../legacy/samechain-fill-v1-pre-fill2-20261006/manifest.json) under their original identities, not conversion or runtime fallback. New guest/program needs specifically authorized new immutable authority and genuine all-mode target/recovery qualification before money use, no automatic migration. [Native status](../NATIVE-IMPLEMENTATION-STATUS.md) alone records current execution/program evidence and completed independent source reviews; independent source/setup/program qualification remains UNVERIFIED.

### Independent manual path — core native acceptance

Using a clean owner-controlled process and retained tool/artifacts, restore the encrypted bundle, inspect original deployment/rules, reconstruct source/target state, prepare/prove the **currently authorized** action locally, build/simulate exact call, obtain explicit user signing permission, submit via own node/selected arbitrary relay, reconcile actual effects and retry valid entitlement. These are interface goals, **not existing `ziquid` commands**; current CLI allocation/generated fixtures do not exercise funded money.

Before native arming, owner retains note control. After arming there is no generic cancel/exit button: S uses valid source resolution evidence and U independently proves eligible payout. Full arbitrary hostile-T terminal witnesses and independently executable **actual S-authorized excess-return capability** must already be available before route enablement; currently missing. A zkVM/target contract cannot recover concealed other-party input openings or sign source ZEC return. Company-off recovery requires chain/data/prover/gas/inclusion assumptions, not guaranteed liquidity or recovery during chain halt.

## 4. Proof thay đổi khác anchor/effects; dependency lifetime

[ZIP229](https://zips.z.cash/zip-0229) and [ZIP374](https://zips.z.cash/zip-0374), interpreted with the pinned cohort in [native status](../NATIVE-IMPLEMENTATION-STATUS.md), distinguish v6 effects from authorizing anchors/proofs. Research alternatives involving delegated U FVK are historical, **not current permission**.

- **Final Q does not autonomously reanchor.** New anchor/proof requires private witness and new proving capability; same effects may retain applicable authorization identity, but actual proof/binding/extraction still must validate. S's final transaction alone cannot supply those inputs.
- Old anchor is not automatically age-expired; source consensus/history/pinned policy determines admissibility. Fees/recipient/value/input/expiry/branch changes are effect changes, not anchor updates; never assume released transaction revoked.
- Preserve original proof source/executable/parameters, VK/program, schema/encoding/history policy, private witnesses and actual public bytes until terminal. [Destination lifetime](destination-settlement.md#5-dependencies-và-version-lifetime) cannot be replaced by registry `latest`. Source upgrades can still affect transaction mineability; preserving a verifier is not preserving a usable Q.
- No cross-app shared viewing/key/witness store; optional Zoss message roster/epoch/revocation or library/SDK release cannot retire funded financial rights. Raw acquisition provenance is not accepted validity.

Source/payment privacy, public destination/linkage and market/matcher privacy are distinct. This owner model does not solve inherited strict GD2 structural FAIL or grant output-leakage waiver.
