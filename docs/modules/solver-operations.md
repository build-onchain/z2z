# Solver operations — crates/runtime, persistence và workers

**Owner contract; migrated runtime/persistence, full native solver orchestration absent.** `crates/runtime` exports PostgreSQL `database`/`store`, encrypted owner-local `custody` and migrated `market` ledger/coordinator/replica/process/inspection modules; `ziquid` retains its native commands, while `z2z-node run` adds only bounded authenticated direct-peer transport. It composes `protocol`, `zcash` and `proofs`, not aliases into sibling Kerb. It still lacks the complete financial signer/send/prover/settlement/reconciler and terminal inventory release. The Zoss raw acquisition seam remains under `zcash`, not mandatory messaging. SQL code is compiled only, **NOT RUN pending private URI; no local SQL tests**. Local records/custody, synthetic market effects and successful transport handshakes are not authentic native arming or permission to move funds.

**Active lane scope:** native ZEC is an active first-class lane (L-ZEC) in the whole pipeline, not V2; L-HEVM, L-SOL, L-NEAR and X.CROSSCHAIN (HTLC first, all pairs in parallel, no atomicity/privacy claim) are active parallel lanes. Runtime composes lane-specific operations under the same owner-authority rules; each lane is reported separately.

[ARCHITECTURE](../ARCHITECTURE.md) owns money behavior; [MODULES](../MODULES.md) packaging; [BLOCKERS](../BLOCKERS.md) gates; [native status](../NATIVE-IMPLEMENTATION-STATUS.md) evidence; [SQL-VERIFICATION](../SQL-VERIFICATION.md) URI-provisioned SQL checks. [SERVER-INDEPENDENCE](../SERVER-INDEPENDENCE.md) owns company-off bundles/stages/drills. Autonomous full implementation permission supersedes routine design waits, not signing/source broadcast/funding/deployment/new private-view delegation or operational-data migration; cutover closes no financial/privacy gate.

## 1. Role và conceptual inputs/outputs

**Replaceable workers automate existing actor rights; they are not financial authority.** Runtime composes exact quote/preparation/inventory/chain/proof/submission/reconciliation operations. S signer owns explicit funding/source-return authorization, U wallet owns P/Q/new-fill signing and its keys, and receiving-chain rules own allocations. Discovery/matching/prover/observer/relay may be stopped/replaced without company admission signature for a qualifying existing right. Losing matcher/counterparty can prevent **new fills**; no liquidity/inclusion guarantee.

### Direct node transport usage — transport-only prerequisite

The selected compatible dependency is `libp2p =0.56.0` with `tokio`, `tcp`, `noise`, `yamux`, `ping`, `identify`, `macros`, `ed25519` and `kad`; `libp2p-kad =0.48.0` uses the narrowly bounded project-local vendor patch. Tokio adds `net` and `signal`, and the existing Linux `rustix` dependency adds `pipe` for subprocess checks. The newer 0.57.0 dependency cohort conflicts with the retained Zcash SHA-2 prerelease pin and is not substituted by changing wallet cryptography. This transport/output slice is **Linux-only**; help/config parsing remains available elsewhere but starting transport fails explicitly, with no blocking/insecure fallback. It requires no paid service, company endpoint, SQL, wallet keys or proving witnesses. It does not complete Phase 2 or V1; public PeerId/IP and timing remain observable, not anonymous or financially trusted.

Start one node, copy its public `listening.address` (including `/p2p/<PeerId>`), then dial that address from a second process:

```sh
cargo run -p ziquid-runtime --bin z2z-node -- run \
  --listen /ip4/127.0.0.1/tcp/0 --max-peers 8

cargo run -p ziquid-runtime --bin z2z-node -- run \
  --listen /ip4/127.0.0.1/tcp/0 \
  --dial /ip4/127.0.0.1/tcp/LISTENER_PORT/p2p/LISTENER_PEER_ID \
  --max-peers 8 --run-for-ms 5000
```

The first process runs until Ctrl-C. `--run-for-ms` optionally selects 1–3,600,000 ms, then cancels pending connection work, closes live peers and exits. Direct addresses use one literal `/ip4` or `/ip6` + `/tcp`; listen port 0 chooses an available port. Dial requires a nonzero port, non-unspecified/non-multicast IP and expected `/p2p/<PeerId>` authenticated by Noise. No DNS/relay/UDP address, hidden seed, automatic retry or discovery is enabled by default. A failed dial is a public observation, not a failed node or successful trade; a finite no-peer run can exit successfully with zero connections.

Alternatively `run --config PATH` accepts at most 16 KiB of strict JSON, mutually exclusive with all transport and discovery flags:

```json
{
  "schema_version": 1,
  "listen": "/ip4/127.0.0.1/tcp/0",
  "dial": [],
  "max_peers": 8,
  "run_for_ms": 5000
}
```

`schema_version` and `listen` are required; defaults are `dial=[]`, `max_peers=8`, no finite duration, `peer_discovery=false`, `find_peer=null`, `discovery_loopback=false` and `reconnect=false`. Unknown/duplicate fields, wrong types, trailing data, unsupported addresses and out-of-range limits reject before opening transport. Each address is at most 256 bytes; there are at most `max_peers` distinct configured dial PeerIds. `reconnect=true` requires at least one configured dial; `--reconnect` cannot combine with `--config`. Do not put owner secrets into this public config. Exit codes: 0 for help/version or clean shutdown, 2 for CLI/config rejection, 1 for transport/signal/output failure.

`max_peers` is 1–64 and caps active connections, pending inbound handshakes, pending outbound dials and the **lifetime distinct authenticated-peer cohort**, separately; each peer has at most one active connection. **Deliberate ceiling:** after the cohort fills, a disconnected admitted identity may reconnect, but an unfamiliar identity is denied until process restart. This bounds the pinned connection-limit behavior's historical per-peer entries; scalable discovery needs eviction-safe accounting, not a growing peer/block list. Yamux is capped at 8 streams per connection using its supported 0.12 configuration branch, with OnRead backpressure and Noise authentication unchanged. Inbound negotiating streams are capped at 4; per-connection event/handler buffers at 8, dial concurrency at 1, handshake timeout at 10 s. Identify's discovered-address cache is disabled and its codec bounds frames at 4 KiB; received arbitrary agent/address/error text is neither logged nor dialed. These are operational ceilings, **not measured weak-hardware/RAM or abuse-resistance guarantees**.

Stdout is public NDJSON: `node_started`, `listening`, `peer_connected`, `peer_identified`, `peer_ping`, failures/rejections, `peer_disconnected`, `node_stopped`. Started status declares `ephemeral_transport` identity and `transport_only=true`; persistent-identity/discovery/gossip/trading/backing/proof/recovery readiness remains false. Only a successfully completed ping emits `peer_ping` and measured `rtt_ms`. Identify reports only the authenticated PeerId and whether its claimed protocol matches `/z2z/transport/1.0.0`; it never establishes money trust. Errors are categorical on stderr or public failure events. Restart generates a new transport PeerId, so old dial addresses must be refreshed; owner identity/persistence is separate unfinished work. The current-thread loop polls owned swarm connection futures directly, with no detached prover/connection workers; shutdown allows at most 1 s for graceful close, then drops remaining local sockets before reporting zero connected peers. Local forced-close events do not claim remote acknowledgment.

Admitted direct connections explicitly request keepalive: successful five-second pings do not themselves reset libp2p's idle policy, and a healthy peer must remain connected past the 30 s idle window until caller shutdown or remote closure. Ping failure still requests disconnect; reconnection is disabled unless the owner selects the bounded policy below.

Optional `--reconnect` (JSON `reconnect:true`) retains only the original checked `--dial` addresses and expected PeerIds. It permits at most three additional accepted direct submissions per configured peer over the whole run, with monotonic 1/2/4-second backoff; successful reconnection never resets the budget. Only transient transport failure or final disconnect schedules eligible work. Wrong PeerId, self-dial, denied/policy/capacity, missing address and current aborted work do not start retry loops. Connected/pending suppression waits for actual connection events without a repeating timer or consuming an accepted attempt. Public `node_started.reconnect_enabled` and `peer_retry_scheduled { peer_id, attempt, delay_ms }` describe policy/work, not success or financial readiness. Exact pending ConnectionIds, superseded work and deferred final-close requests prevent overlapping submissions or stale failures poisoning a newer connection. Ctrl-C/duration/output failure cancels owned retry work. No identify/DHT address adoption, hidden alternative, automatic repeated lookup or persistent PeerId is added; restarting a remote ephemeral node still requires its new public identity/address.

Controlled reconnect acceptance (2026-10-06): `cargo test --offline --locked -p ziquid-runtime --test node_reconnect_cli --test node_transport_cli --test node_discovery_cli -- --test-threads=1` passed21 actual process checks; `cargo test --offline --locked -p ziquid-runtime --lib node::` passed5 node checks, including three exact scheduler races. Separate real forwarding smoke preserved target/seeker processes and Noise identities, reconnected with fresh identify/ping after path loss, then observed exactly initial+three accepted dials across further loss; both Ctrl-C exits0. Scoped runtime clippy and independent design/source review passed. Wrong expected identity, default-off no redial, unreachable-primary/healthy-alternative, strict config and stop-during-backoff are exercised. These checks do not qualify persistent peer identity, arbitrary internet reachability, partition healing, general bootstrap replacement or financial recovery.

Public records are stack-serialized into at most 1 KiB and written directly once to Linux nonblocking stdout, below the 4 KiB atomic pipe-write ceiling; original descriptor flags are restored when the run ends. No blocking writer thread, unbounded log queue or buffering hides backpressure. A full output pipe causes categorical `OutputBackpressure`, exit 1 and owned-swarm/socket cancellation, **not** successful `node_stopped` or a torn pipe NDJSON record. Runtime/config error diagnostics use their own bounded nonblocking categorical stderr write and tolerate full/closed stderr; merging stdout/stderr with `2>&1` cannot restore a blocking error fallback. A full sink may therefore receive no final diagnostic, but still gets nonzero exit. Keep consuming output if a continuous run is wanted. Nonblocking writes do not qualify regular-file disk latency, terminal-driver behavior, cross-process descriptor ownership or general secure logging; those remain separate operational limitations.

### Optional bounded seeded peer discovery — loopback acceptance verified

`--peer-discovery` serves actual FIND_NODE in `/z2z/peer-discovery/kad/1.0.0`; it is off by default. `--find-peer PEER_ID` requires discovery plus at least one explicit `--dial` seed and starts exactly one lookup after Noise-authenticated identify confirms the seed's transport and Kademlia protocols. There is no hidden seed, automatic/periodic bootstrap, refresh, retry, record/provider publication or caching. The zero-capacity filtered store cannot retain records/providers. No mDNS, LAN interface enumeration, order gossip or market/private witness frame is added.

Discovery seeds and candidate addresses must be one literal public IPv4/IPv6 TCP address with nonzero port and the expected `/p2p/<PeerId>`. Private, link-local, unspecified, multicast, broadcast, unsupported special-use and DNS/relay/UDP addresses are rejected. IPv4-mapped IPv6 follows the underlying IPv4 policy. `--discovery-loopback` (also discovery-required) permits literal loopback for controlled process checks only, not private LAN addressing or internet qualification. Listening may remain loopback independently; it does not claim public reachability.

For a controlled three-process lookup, start T with discovery/loopback flags; start S with the same flags and `--dial T_LISTENING_ADDRESS`; then start A with the same flags, `--dial S_LISTENING_ADDRESS --find-peer T_PEER_ID`. Do **not** give A T's address. Both S and A need `--max-peers 2` for this topology. S shares only a checked owner-selected target address after authenticated protocol confirmation. Identify's advertised addresses and inbound ephemeral source ports are never inserted as discovery routes.

The process holds at most `max_peers` lifetime distinct candidate attempts (initial seeds and failed attempts included), authenticated peers and routing peers; each routing peer has one address. Queries retain at most `max_peers` candidate IDs, one address per entry and 256 encoded address bytes, with a 4 KiB packet ceiling, hard parallelism 1, 10 s query deadline and 5 s substream timeout. The whole response is preflighted before candidate-map/iterator growth; malformed entries or wrong response types cannot become an accepted prefix, and resource failure is sticky and wins timeout/completion races. Raw protobuf parsing still allocates within the packet bound; this is not a zero-allocation claim. Every Kad dial is intercepted before transport: validate all addresses in its routing/query union, deduplicate identical checked addresses, reject distinct/conflicting/poisoned extras and emit one expected-ID explicit dial without extending addresses through behaviours. Rejection returns actual Kad dial-failure bookkeeping.

Public NDJSON adds `node_started.peer_discovery_enabled`, `peer_query_started`, `peer_query_result`, `peer_query_failure` and `peer_discovered`. Query `peer_id` is the requested target; failure reasons are fixed categories. `peer_discovered` carries an untrusted checked candidate PeerId/address, **not authentication**; only `peer_connected` follows successful Noise expected-ID authentication. Lookup success need not mean the requested peer exists, is reachable or controls funds. `discovery_ready`, gossip/trading/backing/proof/recovery readiness remain false. Shutdown immediately disables new lookup/dial work and drops owned handlers with the existing bounded close policy.

Observed acceptance (2026-10-06): preserved vendor/focused suites passed 96 checks; runtime transport/discovery suites passed 15 actual process checks plus two address-union unit checks. The final five discovery process checks passed after the finish-first ResourceLimit correction. Independent three-process smoke supplied A only S's address/T's identity, observed FIND_NODE/candidate/expected-ID Noise/identify/ping, then fresh A↔T ping after S exited and clean shutdown of all three processes. Scoped vendor/runtime clippy and independent source reviews passed. Reproduce with `cargo test --offline --locked -p ziquid-runtime --test node_discovery_cli --test node_transport_cli -- --test-threads=1` and `cargo test --offline --locked -p ziquid-runtime --lib discovery_`; preserved dependency checks use `cargo test --offline --locked --manifest-path vendor/libp2p-kad/Cargo.toml --lib --test client_mode`. This verifies the controlled seeded peer-only prerequisite. Full internet reachability, mDNS, bootstrap replacement/reconnect, partitions, weak-hardware resources and broader P2.09/P2.10/V1 acceptance remain unqualified.

## 3. Durable inventory khác observer cache

### TOTAL capacity contract — actual `ActorStore`

Each inventory record belongs to an explicit **actor, exact destination asset and deployment scope** selected by caller in a configured private PostgreSQL inventory schema. IDs/configuration do not authenticate ownership or pooled/chain balance. The parameter named `available` means **TOTAL allocation capacity including every existing active tracked reservation**, not remaining post-reservation/post-escrow spendable balance:

```text
active = sum(amount for Reserved, FundingPrepared, SubmissionUnknown, Armed)
active + new_amount <= caller_authenticated_total_cap
```

Amounts use checked U256 accounting; `Cancelled` is excluded. Caller must derive/authenticate total scope capacity, excluding unrelated liabilities and execution fees **without subtracting these tracked active amounts twice**. Do not feed already-reduced remaining wallet balance as this cap or claim SQL authenticated the chain inventory. Current cap/scope is a caller trust obligation, not funds verification.

- Reservation binds immutable order/context/amount; operation binds exact order/payload digest. Mismatch rejects, duplicate identical operation is not new funding.
- **Preparing funding irreversibly fences current local cancellation before a transaction hash exists.** Crash/sign/send/no response can already have external effects; `FundingPrepared` remains active. `SubmissionUnknown` and caller-observed `Armed` also retain full capacity.
- Only **unfunded `Reserved→Cancelled` before preparation** frees capacity in existing interface. No finish/paid/refunded/TTL release method exists. Future verified proven-no-effect/terminal reconciliation must be implemented, not inferred from this fence or absent receipt.
- SQL `Armed` means caller-authenticated observation only; it does not verify exact code/amount/context/finality or source payment. Terminal actual asset reconciliation remains missing.

## 4. Invariants, cancellation và pending

1. **Prepare/check/restore before reserve+fund:** independently accepted P/Q/context/recovery resources and capabilities, authentic capacity policy and durable intent; no missing certificate/history/opening solved by asking U FVK.
2. **Fund irrevocably before P authorization:** actual target arming/finality gate belongs to U's independent client. S/runtime quote or journal `Armed` cannot authorize P. After arm, no solver cancel/TTL/admin/timer refund.
3. **Q is not delayed recovery:** S can broadcast complete pure-shielded Q before funding/deadline or race P, with disclosed agreed fee/option grief. Offchain scheduling is not source timelock; QBroadcast/mempool/orphan does not establish refund.
4. **No invented reanchor/replacement:** old anchor may remain valid, but final Q alone cannot prove new anchor. No new fee/recipient/value/input/expiry/branch disguised as retry or U FVK delegation. U alone authorizes P; S may only rebroadcast exact authorized executable P if granted.
5. **Source classification/history, not exact id:** same-effect/new auth is P; earlier bound P/T remains admissible; different T/P′ can pay partially/fully. Full validating history/net all-input relation and approved proportional shares, no gross-only/full-refund shortcut.
6. **All-hostile/excess is full scope:** arbitrary valid mixed T remains reachable despite intended one-note authoring. Missing private owner/value/debit facts or independently executable actual S-authorized C>A return is a **release blocker**, not supported completion. Generic zkVM/target cannot synthesize witnesses or sign source return; Unknown protects funds only.
7. **Actual terminal:** fixed U/S proportional transfers and target consumption atomic/rollback/retry under verified source relation; actual source excess return when required and finality. Queue ack/proof accepted/credit/tx hash/Zoss Delivered never paid/refunded. Nonpaying arbitrary T need not self-return U like Q.
